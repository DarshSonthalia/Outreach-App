# Mandatory AI-Generated Email Copy Integration

## ✅ Implementation Complete

The campaign creation flow now requires AI-generated email copy. When users select leads and continue to Step 3, the system automatically generates professional email copy using OpenAI GPT.

## 📋 What Changed

### Frontend Changes

**File: [src/app/campaigns/new/page.tsx](src/app/campaigns/new/page.tsx)**

#### 1. Import campaignsAI API
```typescript
import { auth, workspaces, campaigns, campaignsAI, mailboxes, leads } from '@/lib/api';
```

#### 2. Add state for generation loading
```typescript
const [generatingCopy, setGeneratingCopy] = useState(false);
```

#### 3. Updated handleCreateCampaign function
```typescript
const handleCreateCampaign = async () => {
    // 1. Create campaign
    const campaign = await campaigns.create(token, workspaceId, {...});
    setCampaignId(campaign.id);

    // 2. Auto-generate email copy
    setGeneratingCopy(true);
    try {
        const draft = await campaignsAI.generateDraft(
            token,
            campaign.id,
            'friendly',      // tone
            'medium',        // length
            true             // include_followup
        );
        // 3. Auto-fill form
        setSubject(draft.subject);
        setBody(draft.body);
    } catch (err) {
        // Graceful error: campaign created, but generation failed
        setError(`Campaign created, but failed to generate copy: ${err.message}`);
    } finally {
        setGeneratingCopy(false);
    }

    // 4. Move to Step 3
    setStep(3);
};
```

#### 4. Updated Step 3 UI
- **Loading state**: Shows spinner while generating copy (2-5 seconds)
- **Info banner**: "This email was generated by AI using your campaign context. Feel free to edit it."
- **Auto-filled fields**: Subject and body are pre-populated
- **Editable**: Users can fully edit the generated content
- **Same buttons**: "Back" and "Preview & Launch" work as before

## 🔧 Technical Details

### API Endpoint Called
```http
POST /api/campaigns/{campaignId}/ai/draft
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json

{
    "tone": "friendly",
    "length": "medium",
    "include_followup": true
}
```

### Response Structure
```json
{
    "subject": "Quick question about {{company}}'s operations",
    "body": "Hi {{first_name}},\n\nI noticed {{company}} is expanding...",
    "followup_subject": "Quick follow-up",
    "followup_body": "Hi {{first_name}},\n\nJust checking in...",
    "personalization_vars_used": ["first_name", "company"],
    "risky_phrases_found": []
}
```

### Models Used
- **Model**: gpt-4.1 (draft generation)
- **Temperature**: 0.3 (creative but consistent)
- **Max tokens**: 400
- **Timeout**: 30 seconds
- **Rate limit**: 30 calls/hour per user

## 🛡️ Error Handling

### Scenario 1: Generation Succeeds
✅ Campaign created, form auto-filled, user can edit and proceed

### Scenario 2: Generation Fails but Campaign Created
⚠️ Shows error message, but campaign still created with empty fields
- User can go back and try again
- Or manually fill in fields
- Not a blocking error

### Scenario 3: Campaign Creation Fails
❌ Entire operation fails, user stays on Step 2, can retry

### Scenario 4: Rate Limit Exceeded
⚠️ HTTP 429 returned
- User sees: "You've used all 30 AI calls this hour. Try again in 1 hour."
- User can still create campaign with manual text

### Scenario 5: OpenAI API Down
⚠️ HTTP 503 returned
- User sees: "OpenAI service temporarily unavailable."
- User can still create campaign with manual text

## 🔍 How It Works (Technical)

### Flow Diagram
```
User clicks "Continue" on Step 2 (leads selected)
    ↓
Frontend: handleCreateCampaign() called
    ↓
1. Create campaign via: POST /api/campaigns
    ↓
2. Generate draft via: POST /api/campaigns/{id}/ai/draft
    {
        "tone": "friendly",
        "length": "medium",
        "include_followup": true
    }
    ↓
Backend: LLMService.generate_campaign_draft()
    ├─ Get workspace wizard context
    ├─ Build prompt with campaign context
    ├─ Call OpenAI gpt-4.1
    ├─ Parse structured output (JSON)
    ├─ Return: subject, body, variables, risky_phrases
    ↓
3. Frontend receives response
    ├─ setSubject(draft.subject)
    ├─ setBody(draft.body)
    ├─ setGeneratingCopy(false)
    ├─ setStep(3)
    ↓
4. UI renders Step 3 with pre-filled form
    ├─ Subject field: editable
    ├─ Body field: editable
    ├─ Follow-up toggle: editable
    ├─ Buttons: [Back] [Preview & Launch]
    ↓
5. User reviews, edits if needed, clicks "Preview & Launch"
    ↓
Same flow as before: preview → launch
```
